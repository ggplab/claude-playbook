# `brunch-apply`: 브런치 작가 신청서를 근거부터 준비하는 스킬

> **주의: 이 스킬이 내는 문안과 샘플 글은 참고용 초안입니다.** 브런치는 에이전트가 쓴 글을 걸러내는 것으로 보입니다(2026년 9월 저자 주변에서 글 8편이 막힌 사례, 공식 안내는 없음). 제출하는 소개, 활동 계획, 서랍 글은 초안을 보고 자기 문장으로 다시 씁니다. 초안을 그대로 붙여 넣지 않습니다.

같은 폴더의 [`SKILL.md`](./SKILL.md)가 그대로 복사해서 쓰는 본문이고, `scripts/`, `references/`, `assets/`가 함께 갑니다.

---

## 무엇을 해결하나

브런치 작가 신청은 작가 소개 300자, 활동 계획 300자, 첨부 글, SNS 주소 네 칸입니다. 후기를 모아 보면 떨어지는 이유는 글솜씨가 아니라 기획과 첨부 글의 불일치입니다. 이 스킬은 네 칸을 한 컨셉으로 묶고, 근거를 URL로 남기고, 컨셉이 브런치 안에 얼마나 있는지 실측한 뒤 문안을 냅니다.

저자는 같은 재료로 1차 미선정(2026-09-17), 2차 선정(2026-09-21)을 겪었습니다. 바뀐 것은 재료가 아니라 틀과 첨부 글이었고, 그 절차를 그대로 스킬로 옮겼습니다.

### 한 줄 사용 예

```
브런치 작가 신청 다시 준비해줘. 지난 기록은 docs/brunch-application.md에 있어.
```

## 들어 있는 것

| 파일 | 역할 |
|---|---|
| `SKILL.md` | 절차 10단계, 완료 판정, 함정 모음 |
| `scripts/brunch_overlap.py` | 브런치 검색 API 인기순 상위 제목으로 겹침 조사표 출력 |
| `references/review-criteria.md` | 공식 심사 기준과 합격 후기 URL 표, 저자 실사고 |
| `references/aside-form.md` | 서랍 저장과 신청 폼 4단계 입력 절차(Aside 브라우저) |
| `assets/record-template.md` | 기록 문서 틀, 제출 이력 표 |

## 따라 만들기

### 1. 폴더 복사

```bash
# 저장소를 받은 폴더에서(Claude Code 개인 전역)
mkdir -p ~/.claude/skills
cp -R 02-skills/brunch-apply ~/.claude/skills/brunch-apply
```

프로젝트 한정으로 쓰려면 `<프로젝트>/.claude/skills/brunch-apply`에 둡니다.

### 2. 저자 환경 값 바꾸기

`SKILL.md`의 다음 값이 저자 저장소 기준입니다. 자기 환경에 맞게 고칩니다.

- SNS 발행본 디렉토리 `sns/published/threads/`
- 문체 가이드 `sns/guides/writing-style.md`
- 기록 문서 위치 `docs/`
- 아이 호칭 규칙(첫째, 둘째)

### 3. 겹침 조사부터 돌려 보기

```bash
python3 ~/.claude/skills/brunch-apply/scripts/brunch_overlap.py "연재 주제어 1" "연재 주제어 2"
```

상위 8건 제목이 표로 나오면 성공입니다. 검색 API는 비공식이라 응답이 바뀌면 브런치 검색 화면에서 손으로 옮깁니다.

---

## 설계 포인트

- **제출은 사람이 누릅니다.** 선택 동의 체크와 "신청서 보내기"는 스킬이 누르지 않습니다. 신청서는 보낸 뒤 고칠 수 없습니다.
- **근거는 URL로만.** 심사 기준과 후기는 `references/review-criteria.md`에 URL과 함께 있고, URL 없는 주장은 넣지 않습니다.
- **총건수가 아니라 상위 제목.** 검색 총건수는 낱말 하나만 맞아도 세므로 판정 근거에서 뺍니다.
