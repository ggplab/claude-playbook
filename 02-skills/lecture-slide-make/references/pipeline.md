# 강의자료 파이프라인: 정본이 두 번 넘어간다

한 덱을 만드는 흐름을 7단계로 갈랐다. 핵심은 **정본(SSOT)이 어디 있는가**가 단계마다 바뀐다는 점이다. 뼈대 생성까지는 JSON, 사람이 손을 대기 시작하면 손질 표면, pptx로 내려 마감한 순간부터는 그 pptx 파일이다.

| 단계 | 누가 | 하는 일 | 정본 |
|---|---|---|---|
| 1. 구조 | AI 주도 | 청중, 장 수, 장별 질문("이 장은 무엇에 답하는가") 확정 | JSON |
| 2. 문안 | AI 주도, 사람 승인 | 장별 제목과 불릿을 JSON에. 개조식 규칙 적용 | JSON |
| 3. 재료 | 사람이 고름 | 스크린샷, 로고, QR을 `assets/shots/`에 | 에셋 폴더 |
| 4. 뼈대 생성 | AI 60~70% | `build_deck.py`로 pptx. 도식은 결정 트리로 프리셋 선택 | JSON |
| 5. 세부 터치 | 사람 30~40% | pptx를 열어 배치, 강조, 이미지 손질 | **pptx 손질본** |
| 6. 검수 루프 | AI 검수, 사람 수정 | 새 컨텍스트에서 지시서를 받고 사람이 pptx를 직접 고친다 | pptx 손질본 |
| 7. 마감 | 사람 | 쪽수 일괄 정리, PDF 변환, 촬영 | pptx 손질본 |

## 손질본이 생기면 재생성하지 않는다

5단계에서 사람이 pptx에 손을 댄 순간 **그 파일이 정본**이다. JSON에서 다시 뽑으면 손으로 붙인 스크린샷과 제목 손질이 전부 사라진다.

- 손질본이 있는 동안 생성기를 다시 돌리지 않는다. 생성기는 고치되 돌리지 않는다. 고친 것은 다음 덱에서 산다.
- 검수 결과는 pptx를 직접 고치지 말고 **"슬라이드 번호 + 무엇을 어떻게"** 지시서로 낸다. 사람이 손본다.
- 손질 내용을 JSON으로 되돌리려면 먼저 `compare_deck.py`로 생성본과 손질본을 대조해 무엇이 바뀌었는지 확정한다.

## 첫 패스는 완성 덱이 아니다

전량 생성 전에 **덱 문법 3안 × 각 3장 = 9장**만 내고 하나를 고르게 한다. 완성본 30장을 받으면 반응이 "방향 수정"이 아니라 "전면 재작업"이 된다. 그리고 슬라이드를 놓고 대화할 때 원고 어디에도 없던 내용이 나온다. 그 재료는 표를 채워 달라고 해서 나오지 않는다.

## 검수 루프는 두 패스다

버전이 오를 때마다 직전 버전과 diff를 뜨고 두 눈으로 본다.

| 패스 | 무엇을 보나 |
|---|---|
| 백지 패스 | 직전 지시서를 모르는 눈으로 처음부터. 새 위반을 잡는다 |
| 대조 패스 | 직전 지시서 항목별 반영 O / 부분 / X. 절반만 고쳐진 것을 잡는다 |

고친 줄에 새 위반이 들어오는 **수정발 회귀**가 흔하다. diff의 추가 줄은 반드시 회귀 관점으로 다시 본다.

## 손질본을 생성기에 되먹인다

사람이 pptx를 손으로 마감하면 그 손질 자체가 생성기 개선 데이터다. 대조는 손으로 하지 않는다.

```bash
python3 scripts/compare_deck.py <생성본.pptx> <손질본.pptx>
```

| 신호 | 뜻하는 것 |
|---|---|
| ▪ 있는 장이 손질본에서 급감 | 마커를 끄는 게 맞다 (`marker: false`) |
| 손질본에만 있는 폰트 크기 | 사다리에 없는 단. 새 유형이 필요하거나 단을 잘못 골랐다 |
| 생성본에 많은데 손질본에서 사라진 크기 | 그 단이 통째로 거부됐다 |
| 이미지 있는 장이 손질본에서 급증 | 자산이 안 붙어 나갔고 사람이 손으로 채웠다 |
| 장당 어절 중앙값 격차 | `_meta.density.words_per_slide_max`를 재조정한다 |

결과를 반영할 곳은 문서가 아니라 **생성기와 JSON 기본값**이다. 이번에 배운 것을 다음 덱이 자동으로 물려받아야 같은 간극이 재발하지 않는다.
