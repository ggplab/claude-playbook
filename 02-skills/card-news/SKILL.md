# card-news: 카드뉴스 덱 생성

카드뉴스를 만들 때마다 디자인 규칙을 다시 해석하고 렌더러를 새로 짜지 않기 위한 스킬.
규격은 엔진에 굳어 있고, **매번 손대는 파일은 콘텐츠 JSON 하나뿐**이다.

```
content.json (콘텐츠)  ->  template.html (엔진)  ->  build.py  ->  card-NN.png
      ^ 이것만 편집          손대지 않는다          규격 실측 판정
```

## 규격 (모바일 공유 티어)

카드는 노트북에서 만들지만 휴대폰에서 읽힌다. 1080px 카드가 카톡에서는 폭 390px로 줄어드므로
글자 하한은 절대 크기가 아니라 **축소율**로 정한다. 아래 값은 `build.py` 상단 상수와 짝이다.

| 항목 | 값 |
|---|---|
| 캔버스 | 1080×1350 (4:5) 기본. 정방형 1080×1080도 허용 |
| 글자 크기 | 서로 다른 크기 **3단 이하** (64 / 40 / 32px). 하한 `11 ÷ (390 ÷ 캔버스폭)` = 1080에서 **30.5px** |
| 텍스트 색 | 실제 배경과의 대비 **4.5:1 이상**. 연한 회색은 선에만 쓰고 글자에 쓰지 않는다 |
| 카드당 항목 | **6개 이하** |
| 문장부호 | em dash(`—`), en dash(`–`), 가운데점(`·`) **금지**. AI 말투 흔적이라 카드에서 뺀다 |

## 절차

**1. 입력 확인**
- 소재(원문, 요약, 리서치 노트), 카드 수(기본 5~8), 캔버스(카톡, 스레드, 인스타 전부 같은 규격)
- 원문이 길면 먼저 읽고 요약한다. 요약 없이 카드로 자르면 카드가 목차가 되어 버린다.

**2. 서사 설계: 카드를 나열이 아니라 흐름으로 짠다**
- 기본형: 표지 -> 문제 제기 -> 규칙과 근거 n장 -> 다음 액션
- **한 카드 한 메시지.** 카드 제목만 이어 읽어도 이야기가 되는지 확인한다.
- 항목 6개를 넘기고 싶으면 내용을 줄이는 게 아니라 **카드를 쪼갠다.**
- 시점은 상대 표현으로 쓴다. "이번 달"이 아니라 "신고 전에". 석 달 뒤에 열어도 말이 되어야 한다.

**3. 콘텐츠 JSON 작성**
- `content.example.json`을 복제해 `cards`만 갈아 끼운다. 카드 타입은 `cover`와 기본형(label + title + items + note) 둘.
- `meta.outdir`에 출력 폴더를 지정한다. 전달용이면 바탕화면 폴더가 편하다.
- 강조는 `**...**`만 쓴다. 크기를 키우지 않고 색과 굵기로만 계층을 만든다(3단 규칙).
- `items[].accent: true`면 그 항목 제목이 강조색이 된다. 카드당 한두 개까지만.
- 제목과 출처는 카드 안에 넣는다. PNG로 나가면 이미지 바깥의 글자는 전부 사라진다.

**4. 빌드 (판정 포함)**
```bash
python3 ~/.claude/skills/card-news/build.py <content.json>
```
- `PASS`가 나야 PNG가 생긴다. `FAIL`이면 PNG를 만들지 않고 이유를 출력한다.
- 하단 여백이 24px 미만이면 `!` 경고가 뜬다. 실패는 아니지만 문구를 줄이는 편이 낫다.
- Chrome이 없다는 FAIL이 뜨면 Chrome을 설치하거나 `CARD_NEWS_CHROME` 환경변수에 브라우저 실행 파일 경로를 넣는다.

**5. 눈 검수: 최소 3장을 이미지로 Read**
표지, 가장 항목이 많은 카드, 마지막 카드. 통과 기준을 명시적으로 본다.
- 제목 줄바꿈이 조사만 남기고 끊기지 않았는가 (예: "판단 기준\n은")
- 마지막 줄이 하단 여백을 침범하지 않았는가
- 이모지가 네모(두부)로 깨지지 않았는가
- 표지 제목이 의도한 행 수로 끊겼는가

**6. 전달 준비**
- 전달이 목적이면 전달 문구를 함께 만들고 출력 폴더를 연다.
- 카카오톡은 여러 장을 한 번에 보내면 순서가 섞일 수 있으므로 순서 확인을 안내한다.
- 만든 카드를 자기 자신에게 한 번 보내 본다. 판정은 휴대폰 화면에서 난다.

## 하지 않는 것

| 요청 | 처리 |
|---|---|
| 개념 도식 한 장, 발표 슬라이드 덱 | 이 스킬 밖. 카드뉴스 형식이 아니다 |
| 스레드, 링크드인 본문 글 | 이 스킬 밖. 카드는 본문의 요약이다 |
| SNS 실제 게시와 업로드 | 이 스킬 밖. 사람이 한다 |

## 완료 판정

```bash
python3 build.py <content.json>     # -> PASS + "카드 N장" 출력
ls <outdir>/card-*.png | wc -l      # -> 정의한 카드 수와 같아야 한다
```

`build.py`가 실제로 실패를 잡는지 확인하려면 항목을 7개로 늘리거나 가운데점을 하나 넣어 본다.
둘 다 `FAIL`로 떨어져야 정상이다.

## 구현 메모

- **렌더러는 Chrome headless.** playwright, npm, pip 설치가 필요 없다. 캔버스와 출력 해상도가 같으므로 배율은 1x다.
- **규격 검사는 브라우저 실측이다.** `template.html` 안의 자가검사 스크립트가 `getComputedStyle`로 실제 적용된 크기와 색과 배경을 재고, `build.py`가 `--dump-dom`으로 회수한다. 정적 CSS 파싱은 캐스케이드를 못 풀어서 "CSS 파일 검사"가 되어 버린다.
- **넘침은 `getBoundingClientRect` 비교로 잰다.** `overflow:hidden`이라 화면에서는 잘린 글자가 티가 나지 않는다.
- 색을 바꾸려면 `template.html`의 `:root` 변수만 바꾼다. 크기 클래스는 늘리지 않는다.

### 알려진 한계

- **1080×1080(정방형)은 코드상 지원하지만 실측하지 않았다.** 검증한 것은 1080×1350뿐이다. 정방형을 처음 쓸 때는 `padding: 88px`와 `.title` 여백이 낮은 캔버스에서 여전히 맞는지 눈으로 확인한다.
- **출력 경로는 `meta.outdir`로 매번 지정한다.** 카드뉴스는 목적지(전달 폴더, SNS 초안, 프로젝트)가 건마다 다르다.
- 카드 타입은 `cover`와 기본형 둘뿐이다. 인용이나 통계 강조 같은 타입이 필요해지면 `template.html`에 추가하되, **크기 단계는 늘리지 않는다**(3단 규칙).
