# `card-news`: 카톡으로 보내도 읽히는 카드뉴스를 JSON 한 장으로 만드는 스킬

> 노트북에서는 멀쩡했던 카드가 카톡에 올리는 순간 글자가 안 보이던 경험. 이 스킬은 규격을
> 엔진에 굳혀 두고, 여러분은 **내용 JSON만** 씁니다. 규격에 안 맞으면 PNG를 만들지 않습니다.

같은 폴더의 [`SKILL.md`](./SKILL.md), [`build.py`](./build.py), [`template.html`](./template.html),
[`content.example.json`](./content.example.json) 네 파일을 그대로 복사해서 씁니다.

---

## 무엇을 해결하나

카드를 만들 때 우리는 노트북 화면으로 봅니다. 1080px 이미지가 큼직하게 뜨니 글자도 잘 보입니다.
그런데 카톡에 올리는 순간 받는 사람의 휴대폰에서는 **폭 390px로 줄어듭니다.** 32px로 보이던 글자가
11px가 됩니다. "보기엔 괜찮았는데 카톡에 올리니 안 보인다"는 일이 여기서 생깁니다.

이 스킬은 그 기준을 사람이 매번 기억하지 않도록 **스크립트가 실측 판정**합니다.

| 검사 | 기준 | 어기면 |
|---|---|---|
| 글자 크기 단계 | 한 카드에 3단 이하 (64 / 40 / 32px) | FAIL |
| 최소 글자 | 30.5px 이상 (휴대폰에서 11px) | FAIL |
| 글자와 배경 대비 | 4.5:1 이상 | FAIL |
| 카드당 항목 | 6개 이하 | FAIL |
| 내용 넘침 | 카드 밖으로 잘리는 글자 없음 | FAIL |
| 하단 여백 | 24px 이상 | 경고 |
| 문장부호 | em dash, en dash, 가운데점 없음 | FAIL |

`PASS`가 나야 PNG가 생깁니다. 규격이 코드에 있으니 **한 번 정한 모양이 매번 같게** 나옵니다.

### 한 줄 사용 예

```
/card-news 이번 분기 회의 규칙 정리한 문서를 카드 5장으로 만들어줘
```

클로드가 원문을 요약하고, 서사를 짜고, JSON을 쓰고, 빌드해서 이렇게 보고합니다(예시).

```
PASS
  카드 6장 / 캔버스 1080x1350 / 글자 하한 30.5px
  출력: ~/Desktop/card-news-example
```

같은 폴더에 `card-01.png`부터 `card-06.png`까지 생깁니다. 첫 장은 표지입니다.

## 스킬 파일 해부

```
content.json (내용)  ->  template.html (엔진)  ->  build.py  ->  card-NN.png
      ^ 이것만 편집          손대지 않는다          규격 실측 판정
```

| 파일 | 역할 | 손대는가 |
|---|---|---|
| `SKILL.md` | 클로드에게 주는 절차. 요약, 서사 설계, JSON 작성, 빌드, 눈 검수 | 처음 한 번 |
| `content.example.json` | 카드 내용. 이걸 복제해 `cards`만 갈아 끼운다 | 매번 |
| `template.html` | 카드 CSS와 자가검사 스크립트 | 색 바꿀 때만 |
| `build.py` | JSON을 HTML로 조립하고 Chrome으로 재고 찍는다 | 안 건드린다 |

### 내용 JSON은 두 가지 카드 타입뿐

```json
{ "type": "cover", "eyebrow": "팀 운영 규칙", "title": "회의 시간을\n절반으로 줄이는\n규칙 다섯 가지",
  "sub": "다음 주 회의부터 그대로 적용", "foot_left": "팀 전체 공유용", "foot_right": "2026.09" }
```

```json
{ "label": "02. 규칙 1과 2", "title": "안건 없는 회의는\n열지 않습니다",
  "items": [ { "k": "규칙 1. 안건은 하루 전에", "v": "결정할 것과 공유할 것을 나눠 적는다", "accent": true } ],
  "note": "안건을 쓰다 보면 **메시지 한 줄**로 끝날 일이 절반입니다." }
```

- `accent: true`를 붙인 항목 제목만 강조색이 됩니다. 한 장에 한두 개까지.
- `note`에서는 `**굵게**`만 됩니다. 글자를 키우는 문법은 일부러 없습니다.
- 줄바꿈은 `\n`으로 직접 정합니다. 브라우저에 맡기면 "판단 기준" 다음 줄에 "은"만 남는 일이 생깁니다.

### 왜 브라우저로 재나

CSS 파일을 읽어서 검사하면 실제 적용된 값을 모릅니다. 상속과 우선순위 때문에 파일에 32px라고
써 있어도 화면에서는 다를 수 있습니다. 그래서 `template.html` 안의 스크립트가 **브라우저가 실제로
그린 값**을 `getComputedStyle`로 재고, `build.py`가 그 결과를 회수해 판정합니다.

## 따라 만들기 (5분)

### 1. 스킬 복사

Chrome(또는 Chromium, Edge)만 설치돼 있으면 됩니다. 파이썬 패키지 설치는 없습니다.

```bash
mkdir -p ~/.claude/skills/card-news
cp 02-skills/card-news/{SKILL.md,build.py,template.html,content.example.json} ~/.claude/skills/card-news/
```

클로드에게 시켜도 됩니다. 터미널에서 클로드 코드를 열고 이렇게 요청합니다.

```
아래 저장소의 card-news 스킬을 내 컴퓨터에 설치해줘.
https://github.com/ggplab/claude-playbook/tree/main/02-skills/card-news
- 설치가 끝나면 스킬 목록에 보이는지 확인해줘
```

### 2. 예제 빌드로 확인

```bash
python3 ~/.claude/skills/card-news/build.py ~/.claude/skills/card-news/content.example.json
```

`PASS`가 뜨고 바탕화면 `card-news-example` 폴더에 PNG 6장이 생기면 성공입니다.

### 3. 검사가 진짜 도는지 확인

`content.example.json`의 아무 항목에 가운데점(`·`) 하나를 넣고 다시 빌드합니다. `FAIL`과 함께
위치가 찍혀야 정상입니다. 확인했으면 되돌립니다.

### Windows에서 쓰려면

`build.py`가 Chrome 기본 설치 경로를 찾습니다. 다른 곳에 있으면 환경변수로 알려 줍니다.

```
set CARD_NEWS_CHROME=C:\경로\chrome.exe
```

## 왜 이렇게 만드나 (설계 포인트)

- **매번 손대는 파일을 하나로 줄인다.** 카드뉴스는 내용이 매번 다르고 모양은 매번 같아야 합니다.
  둘을 파일로 분리하면 클로드가 모양을 건드릴 일이 없습니다.
- **규격은 글이 아니라 코드에 둔다.** "글자는 32px 이상"이라고 프롬프트에 적으면 지켜질 때도 있고
  아닐 때도 있습니다. 스크립트가 재면 항상 지켜집니다.
- **불합격이면 결과물을 내지 않는다.** PNG가 생기면 규격을 통과한 것입니다. "됐다고 믿는" 상태를 없앱니다.
- **눈 검수를 절차에 남긴다.** 줄바꿈 위치, 이모지 깨짐은 숫자로 못 잡습니다. `SKILL.md`가 클로드에게
  최소 3장을 이미지로 열어 보게 합니다.

## 더 확장하기

- 색을 바꾸려면 `template.html`의 `:root` 변수 여섯 개만 바꿉니다. 크기 클래스는 늘리지 않습니다.
- 인용 카드, 숫자 강조 카드 같은 타입이 필요하면 `build.py`의 `render_card`에 분기를 더합니다.
  단, 새 글자 크기를 만들면 3단 규칙에 걸려 FAIL이 납니다. 그게 의도입니다.
- 정방형(1080×1080)은 `meta.canvas`로 지정할 수 있지만 실측하지 않았습니다. 처음 쓸 때는 하단 여백 경고를 보세요.
- 8장 실습의 [카드 디자인 기준](../../01-hanbit-claude-guidebook/chap8/Chap8_card-design-system.md)은
  이 스킬이 코드로 고정한 규칙의 **글 버전**입니다. 스킬 없이 클로드에게 문서만 주고 만들 때 씁니다.
