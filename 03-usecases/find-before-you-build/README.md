# 새 자동화 만들기 전에 먼저 찾아보기

> 비슷한 걸 이미 만들어 뒀는지 확인하고 나서 새로 시작하기

〈클로드가 다 해줌〉 4장에서 이어집니다.

## 언제 쓰나

"이런 자동화 하나 만들어줘"라고 부탁하기 전, 비슷한 것을 이미 만들어 뒀는지 먼저 확인하고 싶을 때 씁니다. 스킬이나 앱스 스크립트가 하나둘 쌓이기 시작하는 4장 이후부터 특히 유용합니다.

## 하는 법

| 순서 | 할 일 |
|---|---|
| 1 | 새로 만들기 전에 클로드에게 먼저 물어본다 (아래 프롬프트 참고) |
| 2 | 비슷한 게 있으면 새로 만들지 않고, 기존 것의 사용법만 고쳐서 쓴다 |
| 3 | 정말 새로 만들어야 한다면, 만드는 데 드는 내 시간을 시급으로 환산해 "사서 쓰는 것"·"안 만드는 것"과 비교한다 |
| 4 | 다 만든 뒤에는 이름과 용도를 목록 한 곳에 한 줄로 적어 둔다 — 다음에 또 찾을 수 있게 |

```
새로 자동화를 만들기 전에, 내가 이미 갖고 있는 스킬·앱스 스크립트 중에
비슷한 게 있는지 먼저 찾아봐줘. 있으면 그걸 어떻게 고쳐 쓰면 될지 알려줘.
```

## 알아둘 것

- 매번 새로 만들면 나중에 "이게 뭐였더라"가 쌓입니다. 이름·용도·위치를 적어 둔 목록 하나가 가장 저렴한 예방책입니다.
- "만드는 게 재밌어서" 시작하는 자동화는 유지보수 비용을 안 따진 경우가 많습니다. 한 달에 몇 번 쓰는지부터 따져 보세요.
- 이 관점은 지지플랩의 공개 운영 원칙 문서에 있는 "다시 만들지 말고 찾아서 쓴다"는 규칙을 일반 업무용으로 옮긴 것입니다.
