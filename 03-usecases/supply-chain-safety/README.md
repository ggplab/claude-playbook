# 남이 준 명령을 실행하기 전에

> 정체를 모르는 점검 명령·프로그램을 실행하기 전에 확인할 것

〈클로드가 다 해줌〉 5장에서 이어집니다.

## 언제 쓰나

커뮤니티나 메신저에서 "이 명령어로 점검해 보세요" 같은 안내를 받았을 때 씁니다. 5장처럼 깃허브에 저장소를 만들고 외부 코드·프로그램을 가져다 쓰기 시작하는 시점부터 특히 중요해집니다.

## 하는 법

| 상황 | 이렇게 한다 |
|---|---|
| 낯선 명령어(터미널에 붙여넣으라는 것)를 실행하라는 안내를 받았을 때 | 그 명령이 **공식 채널**(제작사 블로그·공지)에도 똑같이 나와 있는지 먼저 확인한다. 안 보이면 실행하지 않는다 |
| "지금 당장", "긴급" 같은 말과 함께 온 안내 | 급할수록 한 번 멈춘다. 실제 침해 대응도 확인이 먼저고 조치는 그다음이다 |
| 뭔가 이상하다고 느꼈을 때 | 의심되는 파일·프로그램 이름을 그대로 두고, 지우거나 되돌리는 큰 조치부터 하지 않는다. 되돌리기 쉬운 것부터 한다 |
| 확인이 끝나고 진짜 문제였을 때 | 문제와 직접 관련된 비밀번호·토큰만 바꾼다. 관련 없는 것까지 전부 바꾸면 정작 필요한 작업이 멈춘다 |

## 알아둘 것

- "점검해 준다는 도구"가 실제로는 두 번째 침해 경로였던 사례가 실제로 있었습니다. 확인되지 않은 도구는 실행하지 않는 것이 원칙입니다.
- 조치에는 순서가 있습니다: **확인 → 막기 → 치우기 → 되돌리기 → 배운 점 적기.** 순서를 건너뛰고 큰 조치(전체 비밀번호 변경 등)부터 하면 정작 일이 멈춥니다.
- 1인·소규모로 일하면 대신 확인해 줄 동료가 없습니다. 그래서 "일단 실행하고 본다"는 충동이 가장 큰 위험입니다.
