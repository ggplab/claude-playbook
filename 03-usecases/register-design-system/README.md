# 디자인 시스템 등록 네 경로

> 6장에서 쓴 방법 말고, 디자인 기준을 클로드에 연결하는 다른 세 가지 길

〈클로드가 다 해줌〉 6장에서 이어집니다.

## 언제 쓰나

6장에서는 `DESIGN.md` 문서를 프롬프트에 첨부하는 방식을 썼습니다. 다른 프로젝트에서 디자인 시스템을 더 정식으로 연결하고 싶을 때 이 네 가지 경로를 참고하세요.

## 하는 법

| 경로 | 준비물 | 비고 |
|---|---|---|
| 기준 파일 첨부 (6장 방식) | `DESIGN.md` 같은 문서 1개 | 가장 간단. 프롬프트에 링크나 파일로 건넨다 |
| 외부 저장소 연결 | 디자인 시스템 코드가 있는 저장소 주소 | > ⚠️ 확인 필요: 등록 화면의 정확한 이름·위치는 버전에 따라 다를 수 있다 |
| 코드 폴더 지정 | 내 컴퓨터 안의 디자인 시스템 코드 폴더 | 클로드 코드처럼 폴더에 직접 접근하는 환경에서 쓴다 |
| 디자인 파일·자산 입력 | 디자인 도구에서 만든 파일, 색상표·아이콘 등 자산 | 코드가 아니라 디자인 산출물을 그대로 준다 |

> 참고: 저장소나 코드 폴더를 연결하는 경로가 화면상 가장 정밀한(최고 충실도) 방식으로 표기되어 있습니다. 코드로 값이 고정되어 있어 클로드가 임의로 해석할 여지가 적기 때문으로 보입니다.

## 알아둘 것

- 네 경로 중 뭘 고르든 목적은 같습니다. 클로드가 매번 같은 색·글꼴·간격을 쓰게 만드는 것입니다.
- 남의 디자인 시스템을 가져다 등록할 땐 라이선스를 먼저 확인하세요. 공개돼 보이는 것과 써도 되는 것은 다릅니다(6장 꿀팁알려줌 참고).
- 등록 화면 구성은 자주 바뀝니다. 정확한 메뉴 이름은 직접 접속해 확인하는 편이 안전합니다.
