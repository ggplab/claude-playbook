# 9장. 알아서 기록되는 업무 시스템 만들기

클로드 코드 세션이 끝날 때마다 그날 한 일이 저절로 기록되게 만듭니다. 쌓인 기록은 깃허브에 올라가고, 매주 금요일 요약이 디스코드로 도착합니다.

## 실습 자료

| 항목 | 내용 |
|------|------|
| 유즈케이스 | 세션이 끝날 때마다 업무일지가 저절로 쌓이고, 매주 금요일 그 요약이 디스코드로 도착하게 만들기 |
| 사용 기능 | 훅(Hooks), settings.json, 비공개 저장소, 깃허브 액션, 디스코드 웹훅 |
| 산출물 | 세션 종료 훅, 업무일지(`work-log.jsonl`), 일지 전용 비공개 저장소, 금요일 자동 집계, 로컬 대시보드 |

## 이 장의 흐름

| 절 | 하는 일 |
|---|---|
| 9.1 [Plan] | 세션과 훅 이해하기, 프로젝트 폴더 준비, `plan.md`로 자동화 구조 정리하기 |
| 9.2 [Build] | 세션 종료 훅 걸기, 가이드 문서 받기, 깃허브와 디스코드 설정, 발송 테스트 |
| 9.3 [Sustain] | 카드 형태 보고로 바꾸기, 대시보드로 넓히기 |

## 파일

| 파일 | 쓰임 |
|------|------|
| [`WORKLOG_FORMAT.md`](./WORKLOG_FORMAT.md) | 업무일지 기록 형식 기준본. **계획서를 만들거나 훅을 걸 때 클로드에게 함께 준다** |
| [`outputs/`](./outputs) | **9장을 완주해서 나온 산출물 기준본.** 따라 하다 막혔을 때 "제대로 나온 모양"을 확인한다 |

## 형식 기준 쓰는 법

형식을 프롬프트에 일일이 적는 대신 이 문서를 링크로 건네면 됩니다.

```
일지 형식은 아래 문서를 그대로 따라줘. 파일 규칙과 한 줄에 적을 항목이 거기 있어
https://github.com/ggplab/claude-playbook/blob/main/01-hanbit-claude-guidebook/chap9/WORKLOG_FORMAT.md
```

7장의 `DESIGN.md`, 8장의 카드 디자인 기준과 같은 방식입니다. 기준을 문서로 고정해 두면 프롬프트가 짧아지고, 여러 번 요청해도 결과가 흔들리지 않습니다.

## 시작하기 전에

이 장은 8장에서 입문한 클로드 코드(CLI) 환경을 그대로 씁니다. 터미널이 낯설다면 8장 앞부분을 잠깐 복습하고 오면 충분합니다.

그리고 **훅은 물어보지 않고 실행되는 장치**입니다. 이 장에서 거는 훅은 사용자 폴더 설정에 들어가므로, 어느 폴더에서 일하든 세션이 끝날 때마다 동작합니다. 무엇이 걸렸는지는 9장 본문의 방식대로 설명을 함께 받아 두세요.

## 주의

업무일지에는 **내가 작업한 폴더 이름과 파일 이름이 그대로 남습니다.** 회사 자료나 개인 자료를 다룬 폴더에서 세션을 열었다면 그 이름도 적힙니다.

일지 저장소는 반드시 **비공개(private)** 로 만드세요. 9.2.3에서 저장소를 만들 때 확인하는 단계가 있습니다.

디스코드 웹훅 주소는 비밀번호처럼 다룹니다. 주소를 아는 사람은 누구나 그 채널에 글을 올릴 수 있습니다. 채팅창이나 파일에 붙여넣지 말고 깃허브 Secrets에만 넣으세요. 노출됐다면 디스코드에서 웹훅을 지우고 새로 만들면 됩니다.

### 9.1.3 plan.md로 자동화 구조 정리하기 (plan.md 파일 작성하기)

```
이 장에서 만들 업무 기록 자동화의 계획서를 현재 폴더에 `plan.md`로 작성해 줘.
아직 실제 작업은 하지 말고 계획만 작성해 줘. 네가 임의로 정한 내용은 맨 아래 `가정` 항목에 모아 적어 줘.
- 목표: 클로드 코드 세션이 끝날 때마다 업무 기록이 자동으로 쌓이고, 매주 금요일 한 주의 기록을 요약해 디스코드로 전달한다.
- 저장 위치: 어느 폴더에서 작업하더라도 업무 기록은 현재 `work-log` 폴더 한곳에 모은다.
- 기록할 내용: 시작 시각, 종료 시각, 작업한 폴더 이름, 새로 만들거나 수정한 파일 이름
- 산출물:
1. 세션 종료 훅
2. 업무 기록 파일
3. 업무 기록을 보관할 비공개 깃허브 저장소
4. 매주 금요일 자동 발송하는 GitHub Actions와 Discord 연동
- `plan.md` 구성: 목표 / 산출물 / 만드는 순서 / 내가 직접 해야 하는 일 / 가정
지금은 `plan.md` 외에 다른 파일을 만들거나 수정하지 말고, 훅도 설정하지 마.
작성한 뒤 `plan.md`를 열어 보여 줘.
```

### 9.2.1 훅으로 업무 일지 자동 전송하기

```
plan.md를 읽고 계획에 따라 세션 종료 훅을 설정해 줘. 설정이 끝나면 다음 내용을 정리해서 설명해 줘.
- 어떤 훅을 설정했는지
- 훅이 어느 설정 파일에 저장되었는지
- 업무일지가 어느 위치에 어떤 이름으로 저장되는지
- 이 세션을 종료한 뒤 훅이 정상적으로 실행되었는지 확인하는 방법
필요한 결과물까지 모두 만들어 줘. 중간에 되묻지 말고 한 번에 진행해 줘.
```

### 9.2.2 세션 재개하고 설치 가이드 받기 (가이드 문서 작성하기)

```
깃허브가 연결되어 있는지 먼저 확인해 줘. 로그인이 필요하면 알려 줘.
그다음 `plan.md`를 읽고, 디스코드 설정이 필요한 작업을 제외한 나머지는 모두 진행해 줘.
마지막으로 내가 직접 해야 하는 일만 안내 문서로 만들어 보여 줘. 디스코드 계정이 없으니 가입부터 서버·채널 만들기, 웹훅 URL 발급, GitHub Secrets 등록까지 단계별로 설명하고, 각 단계의 확인 방법도 함께 적어 줘.
휴대폰으로 보며 따라 할 것이므로 간단하고 명확하게 작성하고, 실제 주소나 비밀값은 넣지 말고 빈칸으로 표시해 줘.
중간에 되묻지 말고 가능한 작업은 한 번에 끝까지 진행해 줘.
```

### 9.2.4 깃허브 서버 세팅하고 테스트하기 (깃허브 서버 세팅하기)

```
연동된 깃허브 저장소의 링크를 알려 줘.
```

### 9.2.4 깃허브 서버 세팅하고 테스트하기 (메시지 발송 테스트하기)

```
디스코드 Webhook URL생성했고, Github Actions에 Secret도 입력했어. 이제 나머지 절차를 진행해 줘.
```

### 9.3.1 카드 형태로 보고받기

```
디스코드에서 메시지를 확인했어. 프로젝트별 작업 시간은 잘 정리됐는데, 어떤 일을 했는지 한눈에 보기에는 가독성이 조금 떨어져.
현재 자동화 구조는 유지한 채, 디스코드 메시지를 더 보기 쉬운 카드 형태로 개선할 수 있는 안을 3가지 제안해 줘. 각 안의 구성과 장단점을 간단히 설명하고, 바로 수정하지 말고 내가 선택할 때까지 기다려 줘.
```

```
1안을 반영하고 테스트까지 진행해 줘.
```

### 9.3.2 대시보드로 보고받기

```
디스코드와 별개로, 주간 업무 요약을 주기적으로 확인할 수 있는 로컬 대시보드를 만들어 줘.
배포하지 않고 내 컴퓨터에서만 사용할 거야. 현재 업무 기록이 충분하지 않으니 목업 데이터를 사용하되, 실제 데이터가 아니라는 점을 화면에 명확히 표시해 줘.
간단한 프로토타입 형태로 만들고, 이전에 사용한 디자인 시스템을 적용해 줘. 지금은 파일 정보 위주로만 기록되어 있으니, 세션 기록을 바탕으로 어떤 일을 했는지도 파악해 짧은 업무 요약으로 함께 보여 줘.
```

AI는 같은 프롬프트에도 표현이 조금씩 달라질 수 있습니다. 결과가 이 폴더의 기준본과 다르더라도 동작이 같으면 괜찮습니다.
