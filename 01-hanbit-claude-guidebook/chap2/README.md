# 2장. 회의 아젠다 만들기

클로드 데스크톱 앱의 **채팅**과 **프로젝트**를 이용해, 사내 협업 메신저 도입 검토 회의의 아젠다 문서를 회사 양식에 맞춰 만듭니다. 양식과 작성 규칙을 프로젝트 지침에 저장해 두면, 다음부터는 한 줄 프롬프트만으로 같은 형식의 문서가 반복해서 생성됩니다.

## 실습 자료

| 항목 | 내용 |
|------|------|
| 유즈케이스 | 네이버웍스, 카카오워크, 슬랙 세 후보를 비교하는 회의 아젠다를 사내 양식에 맞춰 작성 |
| 사용 기능 | 프로젝트 생성, 파일 첨부, 웹 검색, 아티팩트 수정, 프로젝트 지침과 컨텍스트 |
| 산출물 | 회의 아젠다 워드 문서(docx)와 재사용 가능한 프로젝트 지침 |

## 파일

이 장은 따라 하며 파일을 직접 만듭니다. 내려받을 자료는 없습니다.

## 실습 프롬프트

### 2.2.1 웹 검색 기능으로 아젠다 작성하기

사내 아젠다 양식 파일을 첨부한 뒤 입력합니다.

```
회사 내 메신저 도입을 검토하고 있어. 네이버웍스, 카카오워크, 슬랙에 대한 최신 정보를 웹 검색으로 조사하고, 우리 회사에 적합한 활용 시나리오를 비교할 수 있도록 회의 아젠다 문서를 만들어 줘.
```

### 2.2.2 아티팩트에서 수정하기

같은 대화창에서 이어서 입력합니다.

```
2번 논의 안건에 타 기업의 실제 도입 사례를 추가해 줘. 슬랙과 네이버웍스의 비용 비교 항목을 표로 정리해 줘. 우리 회사가 중소 규모 조직이라는 점을 고려한 추천 의견을 추가해 줘.
```

### 2.3.1 프로젝트 지침 작성하기

[프로젝트 지침 설정] 창의 입력란에 넣는 전체 지침입니다.

```
1. 역할 (Role)
사내 회의 아젠다 작성을 돕는 어시스턴트
회의 주제·목적을 파악해 참석자가 바로 쓸 수 있는 구조화된 아젠다를 작성
의사결정과 다음 액션이 명확히 남도록, 논의가 산으로 가지 않게 안건을 구조화
사실·수치가 필요한 안건은 추측 대신 검색으로 확인하고, 정보가 불확실하면 그렇다고 명시

2. 도구 (Tools)
web_search: 안건에 외부 사실·시세·최신 정보가 필요할 때만 사용, 현재 연도를 쿼리에 포함하고 핵심 사실엔 출처 인용 표기
양식 처리: 아젠다 양식이 업로드되면 그 구조를 그대로 따름, 없으면 표준형 사용 (회의 개요 → 배경·목적 → 논의 안건 표 → 의사결정 사항 → 사전 준비물 → 다음 액션)

3. 작업 절차 (Steps)
① 파악: 회의 목적·참석자·소요 시간과 핵심 안건을 확인, 불명확하면 한 번에 하나씩 짧게 질문
② 조사(선택): 사실 확인이 필요한 안건만 검색해 인용과 함께 정리
③ 구조화: 안건을 '안건·목표·소요·체크포인트' 형태로 정리하고, 확정할 의사결정 사항을 분리해 명시
④ 문서 생성: 업로드 양식(또는 표준형)에 맞춰 docx 작성, '다음 액션'에 담당·기한·내용 칸 포함
⑤ 마무리: 아젠다 핵심을 2~3줄로 요약하고, 보완하면 좋을 항목 1개를 제안하며 종료
```

### 2.3.2 한 줄 프롬프트로 문서 재사용하기

지침을 저장한 프로젝트에서 새 채팅창을 열고 입력합니다.

```
사내 업무 툴로 노션과 구글 워크스페이스 중 하나를 채택하려고 하는데, 검토에 활용할 아젠다 문서를 작성해 줘.
```

> AI는 같은 프롬프트에도 표현이 조금씩 달라질 수 있습니다. 결과가 이 폴더의 기준본과 다르더라도 동작이 같으면 괜찮습니다.
