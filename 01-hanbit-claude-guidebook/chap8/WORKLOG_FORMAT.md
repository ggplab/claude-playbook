# 업무일지 형식

〈클로드가 다 해줌〉 8장 실습 기준본. 세션 종료 훅이 이 형식으로 기록합니다.

훅을 만들 때 클로드에게 이 문서를 함께 주면, 형식을 일일이 설명하지 않아도 됩니다.

## 파일

| 항목 | 규칙 |
|------|------|
| 위치 | 프로젝트 폴더 안의 `업무일지/` |
| 이름 | `YYYY-MM-DD.md` — 날짜 하나에 파일 하나 |
| 같은 날 세션이 여러 번일 때 | 그 파일에 한 줄씩 덧붙입니다 |

## 한 줄의 형태

```
- 시작~종료 (걸린 시간)  작업한 폴더 이름  → 만들거나 고친 파일 이름
  그 세션에서 처음 보낸 요청 (한 줄, 길면 자름)
```

## 예시

```markdown
# 2026-08-07 (금)

- 14:02~15:11 (69분)  tax-research  → report.md, 연말정산_준비_보고서.pdf
  올해 연말정산을 미리 준비하려고 해. 작년과 달라진 내용을 조사해서…

- 16:20~16:45 (25분)  work-journal  → plan.md
  이 장에서 만들 기록 자동화의 계획서를 plan.md로 지금 폴더에 만들어 줘
```

## 규칙

1. 모든 항목은 **프로그램이 계산하거나 그대로 옮깁니다.** 요약을 새로 만들지 않습니다.
2. 첫 요청은 내가 쓴 문장 **그대로** 씁니다. 길면 자르기만 하고 다듬지 않습니다.
3. 파일은 **이름만** 적습니다. 파일 안의 내용은 넣지 않습니다.
4. 그날 파일이 없으면 날짜 제목과 함께 새로 만들고, 있으면 맨 아래에 덧붙입니다.

## 왜 이렇게 정했나

**요약을 만들지 않는 이유.** 요약을 만들려면 클로드를 다시 불러야 하고, 그러면 같은 세션인데도 결과가 매번 달라집니다. 훅은 반드시 실행되고 항상 같은 결과를 내야 하는 자리라, 계산으로 알아낼 수 있는 것만 적습니다.

**그런데도 첫 요청은 넣는 이유.** 시각과 파일 이름만 남기면 한 달 뒤에 봤을 때 그날 무엇을 했는지 떠오르지 않습니다. 첫 요청은 내가 실제로 쓴 문장이라 계산 없이 그대로 옮길 수 있고, 어떤 요약보다 그 세션을 잘 설명합니다.

**문장을 다듬는 일은 나중에.** 사람이 읽을 요약이 필요한 순간은 일지를 쓸 때가 아니라 일주일치를 모아 볼 때입니다. 그 자리는 8장 마지막에 따로 있습니다.

## 주의

첫 요청에는 내가 쓴 말이 그대로 들어갑니다. 가족 구성이나 거주 형태 같은 조건을 적어 요청했다면 그것도 함께 남습니다.

그래서 이 일지는 **비공개(private) 저장소**에 둡니다. 8장에서 저장소를 만들 때 공개 범위를 확인하세요.
