# 업무일지 형식

〈클로드가 다 해줌〉 8장 실습 기준본. 세션 종료 훅이 이 형식으로 기록합니다.

계획서를 만들거나 훅을 걸 때 클로드에게 이 문서를 함께 주면, 형식을 일일이 설명하지 않아도 됩니다.

## 파일

| 항목 | 규칙 |
|------|------|
| 위치 | 업무일지 폴더 안의 `업무일지.md` **파일 하나** |
| 구역 | 날짜마다 `## YYYY-MM-DD (요일)` 제목으로 나눕니다 |
| 줄 | 세션 하나가 표의 한 줄 |

## 한 줄에 적는 것 — 네 가지

| 항목 | 어디서 얻나 |
|------|------|
| 시작 시각 | 세션 기록 첫 줄의 시각 |
| 종료 시각 | 훅이 실행되는 시각 |
| 폴더 | 작업한 폴더의 **마지막 이름만** (`~/Projects/work-log` → `work-log`) |
| 파일 | 새로 만들거나 고친 파일. 작업 폴더 안이면 상대 경로, 밖이면 파일 이름만 |

## 예시

```markdown
# 업무일지

## 2026-08-07 (금)

| 시작 | 종료 | 폴더 | 파일 |
|---|---|---|---|
| 09:12 | 10:40 | work-log | plan.md, scripts/log-session.ps1 |
| 13:05 | 14:22 | apt-dashboard | index.html, DESIGN.md |
| 15:30 | 15:48 | tax-research | - |
```

파일을 하나도 고치지 않은 세션도 기록합니다. 파일 칸에 `-`가 들어갑니다.

## 규칙

1. 네 항목 모두 **프로그램이 계산하거나 그대로 옮깁니다.** 요약을 새로 만들지 않습니다.
2. 파일은 **이름만** 적습니다. 파일 안의 내용은 넣지 않습니다.
3. **읽기만 한 파일은 기록하지 않습니다.** 만들거나 고친 것만 남깁니다.
4. 오늘 날짜 구역이 없으면 제목과 표 머리글을 함께 만들고, 있으면 표 아래에 한 줄 덧붙입니다.
5. 파일이 아주 많은 세션은 앞의 10개만 적고 `외 N개`로 줄입니다.

## 왜 이렇게 정했나

**요약을 만들지 않는 이유.** 요약을 만들려면 클로드를 다시 불러야 하고, 그러면 같은 세션인데도 결과가 매번 달라집니다. 훅은 반드시 실행되고 항상 같은 결과를 내야 하는 자리라, 계산으로 알아낼 수 있는 것만 적습니다.

**폴더 이름만 적는 이유.** 전체 경로에는 내 컴퓨터 사용자 이름이 들어갑니다. 마지막 폴더 이름만 남기면 어떤 프로젝트였는지는 알 수 있으면서 경로는 새어 나가지 않습니다.

**문장을 다듬는 일은 나중에.** 사람이 읽을 요약이 필요한 순간은 일지를 쓸 때가 아니라 일주일치를 모아 볼 때입니다. 그 자리는 8장 마지막에 따로 있습니다.

## 주의

**작업 폴더 밖의 파일은 이름만 남지만, 폴더 이름은 그대로 남습니다.** 회사 자료나 개인 자료를 다룬 폴더에서 세션을 열었다면 그 폴더 이름이 일지에 적힙니다.

그래서 이 일지는 **비공개(private) 저장소**에 둡니다. 8장에서 저장소를 만들 때 공개 범위를 반드시 확인하세요.
