# 8장 알아서 쌓이는 업무일지 만들기

> 집필 진행 중 — 실습 자료는 출간에 맞춰 계속 업데이트됩니다.

## 실습 자료

| 항목 | 내용 |
|------|------|
| 유즈케이스 | 세션이 끝날 때마다 업무일지가 저절로 쌓이고, 매주 금요일 그 요약이 디스코드로 도착하게 만들기 |
| 사용 기능 | 훅(Hooks), 비공개 저장소, 깃허브 액션, 디스코드 웹훅 |
| 산출물 | 세션 종료 훅 · 업무일지 · 일지 전용 비공개 저장소 · 금요일 자동 집계 · 로컬 대시보드 |

## 파일

| 파일 | 쓰임 |
|------|------|
| [`WORKLOG_FORMAT.md`](./WORKLOG_FORMAT.md) | 업무일지 기록 형식 기준본. **계획서를 만들거나 훅을 걸 때 클로드에게 함께 준다** |
| [`outputs/`](./outputs) | **8장을 완주해서 나온 산출물 기준본.** 따라 하다 막혔을 때 "제대로 나온 모양"을 확인한다 |

## 형식 기준 쓰는 법

형식을 프롬프트에 일일이 적는 대신 이 문서를 링크로 건네면 됩니다.

```
일지 형식은 아래 문서를 그대로 따라줘. 파일 규칙과 한 줄에 적을 항목이 거기 있어
https://github.com/ggplab/claude-playbook/blob/main/01-hanbit-claude-guidebook/chap8/WORKLOG_FORMAT.md
```

6장의 `DESIGN.md`, 7장의 카드 디자인 기준과 같은 방식입니다. 기준을 문서로 고정해 두면 프롬프트가 짧아지고, 여러 번 요청해도 결과가 흔들리지 않습니다.

## 시작하기 전에

이 장은 7장에서 입문한 클로드 코드(CLI) 환경을 그대로 씁니다. 터미널이 낯설다면 7장 앞부분을 잠깐 복습하고 오면 충분합니다.

그리고 **훅은 물어보지 않고 실행되는 장치**입니다. 이 장에서 거는 훅은 사용자 폴더 설정에 들어가므로, 어느 폴더에서 일하든 세션이 끝날 때마다 동작합니다. 무엇이 걸렸는지는 8장 본문의 방식대로 설명을 함께 받아 두세요.

## 주의

업무일지에는 **내가 작업한 폴더 이름과 파일 이름이 그대로 남습니다.** 회사 자료나 개인 자료를 다룬 폴더에서 세션을 열었다면 그 이름도 적힙니다.

일지 저장소는 반드시 **비공개(private)** 로 만드세요. 8.4에서 저장소를 만들 때 확인하는 단계가 있습니다.
