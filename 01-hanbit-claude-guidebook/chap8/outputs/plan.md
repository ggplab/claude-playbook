# 업무일지 자동화 계획서

## 목표

- Claude Code 세션이 끝날 때마다, 그 세션의 기록이 `~\Projects\work-log\업무일지.md` 한 곳에 자동으로 쌓인다.
- 어느 폴더에서 일했든 상관없이 모두 이 파일로 모인다. (사용자 레벨 훅이라 폴더를 가리지 않음)
- 매주 금요일, 지난 한 주의 요약이 디스코드 채널로 자동 발송된다.

기록할 내용은 네 가지다.

| 항목 | 값 | 어디서 얻는가 |
|---|---|---|
| 시작 시각 | 세션 첫 메시지 시각 | 대화 기록(transcript) 첫 줄의 timestamp |
| 종료 시각 | 세션이 끝난 시각 | 훅이 실행되는 시점 |
| 작업한 폴더 이름 | 예: `work-log` | 훅이 넘겨주는 `cwd`의 마지막 폴더 이름 |
| 만들거나 고친 파일 이름 | 예: `plan.md, src/app.ts` | 대화 기록에서 Write/Edit 도구가 건드린 파일 경로 |

## 산출물

### 1. 세션 종료 훅

- `~/.claude/settings.json`의 `SessionEnd` 훅 1개.
- 실행 대상: `~\Projects\work-log\scripts\log-session.ps1`
- 하는 일: 대화 기록 파일을 읽어 위 네 항목을 뽑고 → 업무일지.md에 한 줄 추가 → 조용히 커밋·푸시.

### 2. 업무일지.md

- 위치: `~\Projects\work-log\업무일지.md`
- 날짜별 구역 + 표. 사람이 읽기 좋고, 금요일 스크립트가 파싱하기도 쉬운 형식.

```markdown
# 업무일지

## 2026-08-07 (금)

| 시작 | 종료 | 폴더 | 파일 |
|---|---|---|---|
| 09:12 | 10:40 | work-log | plan.md |
| 13:05 | 14:22 | my-site | src/app.ts, src/style.css |
```

### 3. 비공개 저장소

- GitHub 비공개 저장소 `work-log`. 이 폴더 전체를 올린다.
- 세션이 끝날 때마다 훅이 자동으로 커밋·푸시하므로, 저장소의 업무일지는 항상 최신이다.

### 4. 금요일 자동 발송 (GitHub Actions + 디스코드)

- `.github/workflows/weekly-summary.yml` — 매주 금요일 18:00(KST)에 실행. 손으로도 즉시 실행 가능.
- `scripts/weekly-summary.mjs` — 업무일지에서 최근 7일치를 골라 요약문을 만들고 디스코드 웹훅으로 전송.
- 보낼 요약 예시:

```
📋 주간 업무 요약 (08/01 ~ 08/07)

총 9세션 · 14시간 20분 · 파일 23개

• work-log     4세션 · 5시간 10분
• my-site      3세션 · 6시간 40분
• notes        2세션 · 2시간 30분

많이 손댄 파일: src/app.ts(5), plan.md(3), README.md(2)
```

## 만드는 순서

**1단계 — 일지 그릇 만들기**
- `업무일지.md`를 제목만 있는 빈 파일로 생성한다. (형식은 위 산출물 2번대로)

**2단계 — 기록 스크립트 작성**
- `scripts/log-session.ps1` 작성.
- 훅이 넘겨준 JSON(표준입력)에서 `cwd`, `transcript_path`를 읽는다.
- transcript(JSONL)를 읽어 첫 줄 timestamp = 시작 시각, `Write`/`Edit`/`MultiEdit`/`NotebookEdit` 도구 호출의 `file_path`를 모아 중복 제거 = 파일 목록.
- 오늘 날짜 구역이 없으면 만들고, 표에 한 줄 덧붙인다.
- 여러 세션이 동시에 끝날 때 파일이 깨지지 않도록 잠금(재시도) 처리.

**3단계 — 스크립트만 따로 검증**
- 훅을 걸기 전에, 실제 transcript 파일 하나를 직접 넣어 실행해 본다.
- 시각·폴더·파일이 정확히 기록되는지, 같은 날 두 번 실행하면 줄만 늘어나는지 확인.

**4단계 — 훅 등록** *(이 단계부터 사용자 승인 필요)*
- `~/.claude/settings.json`에 `SessionEnd` 훅 등록.
- 사용자 레벨 설정이므로 이때부터 모든 폴더의 세션이 기록된다.

**5단계 — 실제 세션으로 확인**
- 아무 폴더에서 짧은 세션을 하나 끝내고, 업무일지에 줄이 늘었는지 눈으로 확인.

**6단계 — 비공개 저장소 만들기**
- `git init` → `.gitignore` 작성 → 첫 커밋.
- `gh repo create work-log --private --source=. --push`

**7단계 — 훅에 자동 푸시 붙이기**
- 2단계 스크립트 끝에 커밋·푸시를 추가한다.
- 실패해도 세션 종료를 막지 않도록 조용히 넘어간다(네트워크 끊김 등).

**8단계 — 주간 요약 스크립트 + 워크플로**
- `scripts/weekly-summary.mjs`: 업무일지 파싱 → 최근 7일 집계 → 디스코드 웹훅 POST.
- `.github/workflows/weekly-summary.yml`: 금요일 스케줄 + 수동 실행 버튼.

**9단계 — 웹훅 URL을 저장소 시크릿으로 등록**
- 저장소 시크릿 `DISCORD_WEBHOOK_URL`. 코드에는 절대 넣지 않는다.

**10단계 — 발송 테스트**
- 워크플로를 수동으로 한 번 돌려 디스코드에 메시지가 도착하는지 확인.
- 확인되면 금요일까지 그대로 두면 된다.

## 내가 직접 해야 하는 일

| # | 할 일 | 언제 | 방법 |
|---|---|---|---|
| 1 | 디스코드 웹훅 URL 만들기 | 8단계 전 | 요약을 받을 채널 → 채널 편집 → 연동 → 웹후크 → 새 웹후크 → **웹후크 URL 복사** |
| 2 | GitHub CLI 로그인 확인 | 6단계 전 | `! gh auth status` 로 확인. 안 돼 있으면 `! gh auth login` (브라우저 인증) |
| 3 | git 자격증명 연결 | 6단계 전 | `! gh auth setup-git` — 훅이 자동 푸시하려면 필요 |
| 4 | 훅 설정 변경 승인 | 4단계 | `~/.claude/settings.json` 수정 요청이 뜨면 허용 |
| 5 | 웹훅 URL을 시크릿에 넣기 | 9단계 | `! gh secret set DISCORD_WEBHOOK_URL` 실행 후 URL 붙여넣기 (URL을 대화창에 붙이지 말 것) |
| 6 | 첫 발송 결과 확인 | 10단계 | 디스코드 채널에 메시지가 왔는지 확인 |

## 가정

계획을 세우면서 내가 임의로 정한 것들이다. 다르게 원하면 말해 주면 바꾼다.

**훅과 기록 방식**

1. 훅 종류는 `SessionEnd` 하나만 쓴다. 시작 시각과 파일 목록은 대화 기록 파일에서 뽑을 수 있어서, 시작용 훅을 따로 두지 않는다.
2. 훅은 `~/.claude/settings.json`(사용자 레벨)에 넣는다. 프로젝트 레벨에 넣으면 그 폴더에서만 동작하므로 "폴더를 가리지 않는다"는 목표에 맞지 않는다.
3. 기록 스크립트는 PowerShell 7, 주간 요약 스크립트는 Node로 작성한다. 둘 다 이 PC와 GitHub Actions에 이미 있다.

**기록 형식**

4. 시간대는 한국 시간(KST), 24시간 표기. 날짜는 `## YYYY-MM-DD (요일)` 구역으로 나눈다.
5. 폴더는 전체 경로가 아니라 **마지막 폴더 이름만** 적는다. (`~\Projects\work-log` → `work-log`)
6. 파일은 작업 폴더 기준 상대 경로로 적는다. 작업 폴더 밖의 파일이면 파일 이름만 적는다.
7. 읽기만 한 파일은 기록하지 않는다. **만들거나 고친 파일만** 기록한다.
8. 파일을 하나도 안 고친 세션도 기록한다(파일 칸은 `-`). 세션이 끝날 때마다 쌓인다는 목표에 맞춘다.
9. 파일이 아주 많은 세션은 앞의 10개만 적고 `외 N개`로 줄인다.

**저장소와 푸시**

10. 저장소 이름은 `work-log`, 기본 브랜치는 `main`, 공개 범위는 비공개.
11. 세션이 끝날 때마다 자동으로 커밋·푸시한다. 커밋 메시지는 `기록: YYYY-MM-DD HH:MM <폴더이름>`.
12. 푸시가 실패해도(오프라인 등) 세션 종료를 막지 않고 조용히 넘어간다. 다음 세션 때 함께 올라간다.
13. 업무일지에는 **폴더 이름과 파일 이름만** 들어간다. 대화 내용이나 코드는 들어가지 않는다. 그래도 비공개 저장소로 만든다.

**금요일 발송**

14. 발송 시각은 매주 **금요일 18:00 KST** (워크플로에는 UTC `0 9 * * 5`로 적힌다).
15. 집계 대상 기간은 발송일 기준 **직전 7일**(토요일 ~ 금요일).
16. 요약에는 총 세션 수·총 시간, 폴더별 집계, 많이 손댄 파일 목록이 들어간다. 세션 하나하나는 나열하지 않는다.
17. 디스코드 메시지는 2000자 제한이 있어서, 넘치면 폴더별 집계까지만 남기고 줄인다.
18. 그 주에 기록이 하나도 없으면 "이번 주 기록 없음"을 보낸다. (동작 여부를 확인할 수 있어서 침묵보다 낫다)

**범위**

19. Claude Code 세션만 기록한다. 에디터에서 직접 고친 파일이나 다른 도구의 작업은 잡히지 않는다.
20. 이번 문서 작성 단계에서는 훅을 걸지 않는다. 4단계에서 별도로 진행한다.

**중복 방지 (만들면서 알게 되어 추가)**

`SessionEnd`는 세션이 실제로 끝날 때만 오는 게 아니었다. 설정을 고쳐 세션이 다시 읽힐 때도 와서, 같은 세션이 두 번 기록되거나 빈 줄이 생겼다. 그래서 두 가지를 넣었다.

21. transcript에서 timestamp를 하나도 못 찾으면 실제 세션이 아니라고 보고 기록하지 않는다. (파일을 안 고친 세션은 transcript가 정상이라 18번대로 그대로 기록된다)
22. 세션은 (시작 시각, 폴더)로 구분한다. 같은 세션이 다시 들어오면 줄을 늘리지 않고 종료 시각과 파일 목록만 갱신한다.
